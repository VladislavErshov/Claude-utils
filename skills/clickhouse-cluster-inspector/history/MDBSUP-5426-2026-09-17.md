## Фикс shard33/pc: inconsistent sources

`mcc status` показывал живой том на srvm5069 (3684745a/b, создан 17.09 01:02) плюс ДВА мёртвых
NORMAL-дубликата — двухступенчатая миграция оставила два трупа:
- srvm2136: 1951b223 (data 6000G) / 1951b222 (logs) — самый старый том (эра 11ef);
- srvm5082: 12b49da2 / 12b49da3 (2.93T, эра b215) — таргет первой миграции.

Фикс — mcc delete по UUID парами data+logs (инстанс живёт на srvm5069, проверено
`mcc instances` → minion srvm5069; tool_status показывает uuid живого тома):

```bash
mcc --local -n infra -c pc delete 1951b223-...,1951b222-... -f yaml   # srvm2136
mcc --local -n infra -c pc delete 12b49da2-...,12b49da3-... -f yaml   # srvm5082
```

- Уравнение-подтверждение — pexpect (`attempt 0/3\): (\d+)\s*(mod|[-+*/%])\s*(\d+)`), mcc в pipe молчит.
- ⚠️ «New empty volume will be created» в выводе delete — норм: облако создаёт пустые плейсхолдеры
  вместо удалённых девайсов, живой том не трогает.
- ⚠️ После удаления ПЕРВОЙ пары флаг `!!! inconsistent sources` НЕ ушёл (вторая копия оставалась
  NORMAL-источником) — ушёл только после второй. Вывод: флаг чистится, только когда живой том
  остаётся единственным NORMAL-источником; мёртвых копий может быть несколько (по одной на каждую
  недосчитанную миграцию), проверять после каждого delete.

Проверка: `mcc status` — флаг исчез, том MOUNTED; instances — RUNNING; clickhouse-client —
0 readonly / 0 delay / uptime в норме.
