# MDBSUP-5512 — Redis dataportalredisdb: add_hosts застрял, кластер unavailable

Дата: 2026-09-17. Кластер Redis Sentinel `dataportalredisdb`
(`c790ac8e-5b66-494c-9aac-7d7c1f4ade55`, dzen, очередь
`dataportalredisdb-data-portal-redis.data-portal.db.production.mdb.batch`).
Операция add_hosts `9b447196-bf31-452c-baf5-9b7912cf591b` (+ec), 4 failed runs.

## Суть (3 строки)

formReplication падала «All sentinel hosts are unavailable» — сетевые политики (SG)
не пускают mdb-processing-воркеры к 26379/6379 хостов кластера (соседний dzen
wagtail — доступен, т.е. per-cluster). Новый ec-хост при этом был провиженен с
`replicaof hc` (каскад с реплики) в redis.conf → «Sentinel wrong info», кластер UNAVAILABLE.

Довели вручную: REPLICAOF pc + CONFIG REWRITE на ec, SQL (operations→done,
INSERT host_state), op_stop/op_start redis-sentinel.watch → Cluster is AVAILABLE.
Хвосты: MDBDEV-3455 (сетевой доступ), MDBDEV-3456 (баг рендера replicaof).
