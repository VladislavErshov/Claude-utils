# MDBSUP-5269 — rt-filters-adtech-kafka: delete_hosts (8.broker.rc) застрял в операторе из-за дедлока reassign'ов CC (09.09.2026)

- **Кластер:** rt-filters-adtech-kafka `b1248203-3905-471c-b6b7-0dd9c6ba99c8` (project adtech, ns infra)
- **Операция:** `6fa63911-8124-4aa3-bc1a-c95e74dae803` delete_hosts (вывод 8.broker...rc, broker id 22008; rc остаётся 7 брокеров, isWithdrawing=false), failed на `get_kafka_downscale_broker_result`, attempts_left=0, in_processing=false.
- **Суть:** оператор живой (крутил KafkaAdminAction каждые ~5 мин), но вечный цикл «Waiting for broker reassignment check»: на 22008 оставалась `request-log-10`. В кластере 4 партиции request-log (10/24/59/82) сидели в активных reassign'ах от Cruise Control self-healing, заблокированных дедлоком: реплика 23001 вне ISR не возвращается в ISR, пока reassignment активен. CC при этом считал все 8 rc-брокеров «recently removed» (22001–22007 живы).
- **Лечение:** STOP_PROPOSAL_EXECUTION CC + disable self-healing GOAL_VIOLATION → ручной reassign по варианту A (RF=3, rc-реплики выброшены; p10 мгновенно, 24/59/82 с переливкой) → оператор сам дошёл до unregister + withdraw, задача исчезла из оператора → операция закрыта done SQL.
- **Хвосты на момент закрытия тикета:** переливка p24/59/82 ещё шла; throttle-конфиг топика не снят; CC не рестартован (recentlyRemovedBrokers протухшие), self-healing GOAL_VIOLATION отключен.
