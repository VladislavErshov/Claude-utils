# MDBSUP-4892 — смена diskType ssd→nvme для двух Kafka-кластеров (2026-08-26)

## Тикет
https://jira.vk.team/browse/MDBSUP-4892 — «Kafka: смена типа диска с SSD на NVMe для двух кластеров (ok-events, vk-events)».
Причина ручной правки: через UI смена типа диска недоступна («Нельзя изменить тип диска при модификации кластера»).
Пользователь (vl.ershov) сам переводит кластеры на nvme в облаке; задача — синхронизировать прод-БД.

## Кластеры
| name | cluster_id | версий в db_cluster_version |
|---|---|---|
| ok-events (adtech, prod) | 12daef01-ca61-4c6b-b586-f46d06c1c329 | 3 (id 2797 new, 235575 + 235785 create_additional_service) |
| vk-events (adtech, prod) | 12d62bd8-c9d3-4b6b-890f-9eadc3805ef2 | 2 (id 2795 new, 236173 create_additional_service) |

Состав обоих: broker × 3 (hc/kc/pc), controller × 3 (hc/kc/pc), cruise × 1 (pc).

## Где лежит тип диска
Только в `db_cluster_version.cluster_params` (jsonb), два ключа:
- `diskType` — брокеры (TemplateBuilder.ts:102 → DISK_TYPE манифеста);
- `kafkaParams.controller.controllerDiskType` — контроллеры (GenerateKafkaControllerManifestTaskProcessor.ts:40).

`one_cloud_meta` типа диска НЕ содержит (только queue/domain/serviceName).
Cruise-хост использует дефолтный logsDiskType (DbDefaultsManager) — не трогали.
Валидные значения енума: ssd / nvme / hdd.

## Проверки перед правкой
- Активных блокирующих операций нет: последние operations по кластерам — done/canceled
  (add_hosts 828b3bd5 canceled, sys_update_cluster done и т.д.).
- `databases` не содержит disk-параметров (только settings) — трогать нечего.
- host_state у кластеров полный (7 хостов на кластер).

## Применённый SQL (прод, через docker cp + psql -f)
```sql
BEGIN;
UPDATE db_cluster_version
SET cluster_params = jsonb_set(
      jsonb_set(cluster_params, '{diskType}', '"nvme"'),
      '{kafkaParams,controller,controllerDiskType}', '"nvme"'),
    update_ts = now()
WHERE cluster_id IN ('12daef01-ca61-4c6b-b586-f46d06c1c329','12d62bd8-c9d3-4b6b-890f-9eadc3805ef2');
COMMIT;
-- UPDATE 5
```

## Итог
UPDATE 5, верификация: все 5 строк ok-events/vk-events → diskType=nvme, controllerDiskType=nvme (update_ts 2026-08-26 17:58).
Дальше пользователь руками переводит кластеры на nvme-диски в облаке.

## Грабли
- У `operations` нет колонки params (ошибка при SELECT) — проверять по type/status/in_processing.
- `databases` тоже без params — только settings.
