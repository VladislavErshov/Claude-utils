# MDBSUP-5264 — закрытие failed-операции update_user (aclOperation: ANY)

Дата: 2026-09-09. Kafka efkk-kafka-stage `b84e9724-798c-4614-a593-17962807f166`
(проект uchiru), ns судя по хостам — обычный флоу, кластерная специфика не привлекалась.

- Операция `5f32d1a5-fccd-4045-b616-17a9e7184a92` (update_user, пользователь "user")
  упала с `operation must not be ANY` — в ACL запроса передали `aclOperation: ANY`,
  валидация на API это не отсекла. Failed-операция блокировала кластер
  («Already has active or failed operation»).
- Диагностика: статус в прод-БД (failed, in_processing=t, attempts_left=0); в Temporal
  по workflowId=operationId единственный run FAILED, ретрая нет → править безопасно.
- Фикс: стандартный UPDATE operations → done / in_processing=false / finished_ts=now() /
  error_message=NULL (WHERE status='failed'), верификационный SELECT подтвердил.
- Кластерная специфики нет (хосты не трогали) — полный разбор здесь, без ссылки
  в inspector-skill.
- Комментарий в Jira не писали (просьба пользователя: только история).

Возможный баг продукта: API пропускает `aclOperation: ANY` в update_user до workflow,
где тот фейлится и блокирует кластер — стоит завести баг-тикет на валидацию
(предложено пользователю 09.09, отдельного тикета нет).
