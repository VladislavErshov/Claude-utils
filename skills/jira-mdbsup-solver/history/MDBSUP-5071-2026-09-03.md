# MDBSUP-5071 — Redis moneyflowd-billing: delete_hosts kc довелся сам, операторная задача висела месяц

Дата разбора: 2026-09-03. Кластер `moneyflowd-billing-adtech-redis` (`91aa295b-e86d-4bad-82cf-55c73039767d`,
project adtech, Redis Sentinel, ns infra), операция delete_hosts `8527a8fa-57c4-4fc6-964c-104540bf8320`
(хост `1.db.moneyflowd-billing-adtech-redis.kc.one-infra.ru`, старт 05.08 19:07 МСК).

## Суть (3 строки)

Операторная задача `downscale-instances` (redis-sentinel) месяц не исчезала из
`operators.redis-sentinel.tasks` → `get_result_redis_sentinel_downscale_operator` исчерпал
попытки (attempts_left=14), хвост задач остался scheduled. Sentinel-часть при этом отработала
сразу (06.08 22:04 UTC: reset-master + переобнаружение, спам «Failed to resolve hostname kc»
прекратился). 02.09 ~21:02 МСК задача исчезла из tasks (op_stop кем-то по webim или сам оператор —
со стороны mdb-data не видно, в taskinfos задачи уже нет) → get_result закрылся за 0.2 c →
хвост дошёл до done (21:03:47 МСК), через час после создания тикета.

## Проверено 2026-09-03 (всё чистое, правок не потребовалось)

- прод-БД: operation done, все 7 tasks done, host_state = hc/pc/uc;
- облако: в kc инстансов сервиса нет, DNS kc-хоста NXDOMAIN;
- кластер: мастер pc, реплики uc/hc online lag 0, 3 sentinel'а, кворум 2, состояние
  идентично на всех хостах; «sentinel wrong info» не воспроизводится (последняя
  sdown/tilt-волна 02.09 17:11–17:29 МСК — её и видел автор тикета).

## Урок

- get_result-задача завершается сам, как только операторная задача исчезает из tasks —
  перед ручным закрытием SQL (как в MDBSUP-4932) сначала проверить актуальный статус:
  операция могла сойтись сама.
- Вывод kc-хоста из sentinel-состояния при downscale происходит корректно (в отличие от
  old known-peers проблемы из скилла redis-sentinel-inspector — там reset нужен при ручном
  удалении хоста).
