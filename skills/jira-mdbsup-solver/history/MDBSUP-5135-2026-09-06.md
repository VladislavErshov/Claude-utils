# MDBSUP-5135 — cid-kafka: пустой background.threads не дал брокерам стартовать, modify не рестартит FINISHED-хосты

Дата: 2026-09-06. Кластер `cid-kafka` (`84352936-84cc-47c6-abc1-b8b622e5ebc2`), проект dis,
KRaft 4.x, хосты 1.{broker,controller}.* в hc/pc/zc + 1.cruise.hc.

**Суть:** при создании кластера в `brokerConfig.config` ушёл `background.threads=""`
(пустая строка) → все 3 брокера упали на старте, облако после 30-минутного таймаута
«Waiting for port 9092 on lan» поставило `FINISHED / ATTEMPTS_LIMIT`. Контроллеры живы.
Два modify_cluster через UI выставили значение (10 → 15) — операции `done`, но хосты
не рестартовали: modify обновил только PMS/БД, а старт брокеров в облаке никто не
триггерил. Хвост: у всех done-операций остался `in_processing=t`.

**Диагностика:** прод-БД (`db_cluster_version` — история значений, `operations` —
все done), PMS `kafka.broker.properties` на ключе `cid-kafka-dis-kafka.clouds` —
уже `background.threads=15`, `mcc instances` по трём ДЦ — брокеры FINISHED/ATTEMPTS_LIMIT.
Логи брокера напрямую не достать (`mcc logs @console` на FINISHED-хосте рвёт соединение).

**Починка:** `mcc start broker.cid-kafka-dis-kafka` в hc/pc/zc (без delete volumes —
confp перерендерил конфиг из PMS при старте) → все брокеры RUNNING, `kafka-broker active`,
в конфиге `background.threads=15`, в логе «Kafka Server started». Cruise сам вышел из
UNAVAILABLE. SQL: `UPDATE operations SET in_processing=false WHERE status='done'`.
