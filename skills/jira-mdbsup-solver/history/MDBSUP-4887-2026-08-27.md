## Что установлено

- Ошибка — обёртка `MdbVaultClientException("Failed to get secret from " + path, ex)` из
  mdb-commons-lib `proxylib/.../vault/client/VaultClientImpl.java:66` (VaultException при read).
- Читал `KafkaUserActivityImpl.upsertUser` (mdb-processing): `vaultPasswordService.getPassword(
  namespace, dto.vaultPathToPassword())` перед AdminClient-операцией.
- Руна 2 прошла полностью: обе активити COMPLETED, юзер в `users` обновлён
  (updated_ts=15:52:01.86, updated_by=ops_refresh_api, is_deleted=f).
- Первопричину руны 1 (403 vs 404 в vault) установить не удалось — см. грабли.

## Грабли сессии

- **Temporal UI API игнорирует runId в /history** — `?runId=<run1>` возвращает историю
  ПОСЛЕДНЕГО руна (успешного). Историю упавшего руна так не достать; `?runId` на
  `/workflows/{wid}` describe тоже перекрывается последним раном. Export-эндпоинт не пробовали.
- **В логах воркеров operationId не ищется**: java.log покрывает нужный час (проверены
  1/2.uc и 1/2.pc), но grep по `7ba52676` и `oneme_yt_reader` пуст — вероятно, ротация
  gz-архивов и/или MDC логирует не всё. Мdb-data логи тоже пусты по operationId.
- `mcc instances "%.mdb-processing%"` без `-c` показывает только uc — воркеры есть и в pc
  (видны через task-queue pollers Temporal API: `/api/v1/namespaces/default/task-queues/kafka-activities-queue`).
- Таблица `users`: колонка `name` (не username), состояние юзера — `is_deleted/updated_ts/updated_by`.
- Input руна createKafkaUser содержит `vaultPathToPassword` = `zkv/mdb/<project>/kafka/<fullQueue>/users/<user>`
  (то, что в тикете), а в БД `vault_path` = `zkv/data/mdb/...` — это разные ключи (data-маунт).
