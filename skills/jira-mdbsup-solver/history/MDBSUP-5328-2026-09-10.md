# MDBSUP-5328 — logs (recom-wizard): второй delete_hosts за день, та же незакрытая сеть hc→uc

Дата: 2026-09-10. Kafka, ns dzen, кластер `logs` (`f0d28ab1-bbd6-4288-a2f3-958b635a5f3e`),
очередь `logs-recom-wizard-kafka.recom-wizard.db.production.mdb.prod`.
Операция `2fe4211e-319f-4270-9c9c-f4b0b9ffadc1` (delete_hosts, 11.broker...hc, id 20011, 11→10).

## Причина — та же, что в MDBSUP-5304 (утро, тот же кластер)

Таск `kafka.downscale-broker --cloud=hc --replicas=10` (старт 16:21) в precondition:
`isFresh() false` — JMX 7777 {hc,kc,pc}→uc по внутренним fd00-сетям отфильтрован
(SocketTimeout на все uc-брокеры). Сетевой фикс с утра не сделан → **второй зависший
delete_hosts за день на том же кластере**. `kafka.update` стоит с 09-08. Пока сеть не
починят — любая операторная операция по кластеру встанет так же.

## Что сделано (утверждено пользователем, шаги 1–4)

1. `mcc op_stop "queue://..." kafka.downscale-broker` — таск исчез из tasks.
2. Проверка пустоты 20011: du `/mnt/data/log` = 87M, только `__cluster_metadata-0` →
   reassign не нужен.
3. Unregister: `kafka-cluster.sh unregister --bootstrap-server <fqdn>:9092 --config
   /opt/kafka/config/client.properties --id 20011` → «no longer registered».
   ⚠️ Флаг именно `--config`, не `--command-config` (usage отклоняет).
4. `mcc stop 11.broker...hc` → FINISHED/STOPPED; `mcc rescale broker.logs-recom-wizard-kafka 10`
   (pexpect-уравнение) → «FORCED RESCALE to 10».

## Отличие от утра: операция закрылась СА в done

После op_stop get_result-процессор увидел исчезнувший таск и закрыл операцию
`done` в 18:50 — **SQL не понадобился** (утром процессор успел закрыть failed до
исчезновения таска — гонка; исход зависит от момента поллинга). host_state-строку
hc-хоста бэкенд удалил сам.

## Новые грабли (SASL_SSL на 9092 — весь день ушёл на это)

- **9092 = SASL_SSL** (`listener.security.protocol.map=...INTERNAL:SASL_SSL`): все admin-клиенты
  ОБЯЗАНЫ получать `--command-config /opt/kafka/config/client.properties` (SASL_SSL+PLAIN).
  Без него: plaintext→TLS = мусорный ответ → `OutOfMemoryError` в NetworkReceive; с
  конфигом, но без SAN → `SSL handshake failed: No subject alternative DNS name matching localhost found`
  → bootstrap всегда FQDN (не localhost).
- sshexec умирает по ~60с: kafka-topics --list на 100+ топиков не влезает → только
  setsid+nohup+`sleep 5` (канон sshexec.md), прогресс/результат через файлы на хосте.
- Kafka-тулзы пишут INFO-логи в **stdout** → списки топиков фильтровать `grep -E '^[a-zA-Z0-9._-]+$'`,
  describe — `grep -E 'Partition: [0-9]'`; при флапах ретраи внутри скрипта на хосте
  (--list бывает падает, 1-й прогон скрипта дал 0 топиков).
- `--list` вернул 13 топиков/360 партиций (утром было 96/373) — Datatransfer видимо убрал
  свои топики между разборами; на вывод пустого брокера не влияет (ground truth — du).
