# MDBSUP-5423 — Redis social-redis: add_hosts падает с 403 на vault-путь master (2026-09-17, разбор приостановлен)

Кластер `social-redis` `e0f7bf15-6fea-42fe-9c19-4b6345c7118d` (проект social, Redis Cluster),
операция `add_hosts` `6c25421e-6fbd-45ec-89da-2dfc5842ba38` — 4 рана (09.09, 10.09, 14.09 ×2),
все FAILED. Инстансы в облаке поднялись, в MDB не зарегистрированы (5 хостов: shard1 EC+RC,
shard2 EC, shard3 EC+PC).

## Корневая причина (Temporal, последний ран; история старых ран API недоступна)

Родитель: `SHARD_OPERATION_FAILED — One of shard workflows failed`. Все 3 child-workflow
`addRedisClusterReplica` (`6c25421e-..._shard1/2/3`) падают одинаково:

```
INVALID_VAULT_SECRET: Vault secret is missing for path:
zkv/mdb/social/redis/social-redis-social-redis.social.db.production.mdb.prod/master
— Query for vault returned non-200. Status: 403. Error: {"errors":["permission denied"]}
```

Activity читает мастер-пароль из vault для настройки репликации новых реплик → падает,
хосты остаются незарегистрированными.

## Выводы

- **403 персистентная** (4 рана за 5 дней, одна и та же ошибка) — НЕ транзиентная,
  в отличие от MDBSUP-4887 (там самоустранилась за 6 мин). Ретраи бесполезны без
  выдачи прав (или фикса пути).
- Подозрение на **баг генерации пути**: задвоение `social-redis-social-redis...`
  (возможно каноничное `<service>-<fqdn>`, не сверено). Сверить с соседним
  redis-кластером проекта social, где add_hosts проходил.
- Прод-БД (Шаг 0: `operations`/`host_state`/`db_shards`) в этой сессии НЕ снимался —
  docker-демон не поднялся. При возврате к тикету начать с него.

## План решения (согласован, не исполнен)

1. Шаг 0: read-only прод-БД — статус операции, история операций кластера (были ли
   успешные vault-чтения раньше), host_state.
2. Сверить vault-путь с рабочим redis-кластером проекта social → отличить «битый путь»
   от «нет прав на правильный путь».
3. Эскалация владельцам vault/zkv-политик: чтение `zkv/mdb/social/redis/.../master`
   для SA mdb-processing; если путь битый — баг-тикет в mdb-processing.
4. После фикса — retry операции штатно из UI; верификация: ops done, 5 хостов в
   host_state, `master_link_status:up`.
5. Фоллбэк (ограниченный): ручная регистрация по эталону
   [db-worker/history/MDBSUP-4752-add-hosts-stuck-ops.md](../../db-worker/history/MDBSUP-4752-add-hosts-stuck-ops.md)
   — но репликацию руками не поднять без master-пароля из vault, поэтому фоллбэк
   практически закрыт тем же блокером. Предпочтителен путь 3→4.
