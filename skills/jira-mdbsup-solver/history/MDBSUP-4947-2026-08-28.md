# MDBSUP-4947 — Удаление cruise-control из HC (vkvideo-common), пересоздание в EC — на стороне пользователя

- Дата: 2026-08-28
- Кластер: `2e756869-eb6f-4d4f-85fc-359af787b59f` (vkvideo-common, Kafka, ns combo, domain one-infra)
- Хост: `1.cruise.vkvideo-common-combo-kafka.hc.one-infra.ru`

## Суть

Просьба перенести CC из HC в EC; кнопка переноса в UI неактивна, т.к. операции переноса CC
между ДЦ для Kafka не существует (в API только create; modify с другим cruiseControlDc хост
не двигает — только PMS + рестарт в новом ДЦ). Выполнено только удаление CC из HC по канону
MDBSUP-4827; пересоздание в EC — пользователями самостоятельно через UI («Добавить Cruise»,
кнопка активируется после чистки kafkaParams.cruiseControl). Коммент в Jira написан.

**Полный разбор прецедента** (stop → withdraw service → withdraw storage → SQL):
[../../kafka-cluster-inspector/history/MDBSUP-4827-2026-08-25.md](../../kafka-cluster-inspector/history/MDBSUP-4827-2026-08-25.md)

## Дельта к прецеденту

- one_cloud_meta cruise-control-service (fake_id 15115) сохранена — create CC её переиспользует.
- Прежние параметры CC (для пересоздания): autoRebalanceEnabled=true,
  autoRebalanceOnBrokerFailEnabled=true, replicationThrottleMb=50.
- Грабля mcc withdraw: уравнение-подтверждение может быть БЕЗ пробелов вокруг оператора
  (`6*6`), pexpect-regex должен допускать `*` без пробелов: `(\d+) *([+*-]) *(\d+)`.
- После withdraw storage состояние PURGEABLE; `mcc purge "<queue>/cruise" all` →
  «none to purge» — квоты свободны, доп. действий не нужно.
