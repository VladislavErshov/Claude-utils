# MDBSUP-4894 — delete_cluster Kafka g3-prod падает на delete_kafka_pms_settings (26.08.2026)

Кластер g3-prod `60eb282d-9ae1-462a-9e16-4168b5ddb0df` (ns **vkontakte**, 259 хостов),
операция `bed5a048-da13-4214-9858-5ff0e3561196` delete_cluster → failed, attempts_left=0.

## Диагноз (исполнение не проводилось — отдано инфраструктурщикам)

- Temporal пуст по operationId и ClusterId → флоу не темпоральный и не операторский:
  это mdb-backend task chain (`DeleteKafkaPmsSettingTaskProcessor` → `PmsClient.deleteVariable`).
- **«404» — фейковый**: `HttpRestClient.doRequestWithRequestInfo`
  (plugins/common/src/http/HttpRestClient.ts:80) ловит исключение fetch и возвращает
  `new Response(e.message, {status: 404})`. Реальная ошибка — TLS
  `unable to get local issuer certificate`.
- **Причина**: с **23.07.2026** `pms.cloud.vk.team` отдаёт публичный серт `*.cloud.vk.team`
  от **HARICA DV TLS RSA** (публичный GR CA), не внутренний VK CA. CA-бандл ns vkontakte
  (vault `zkv/front/mdb-nodejs.mdb-front/vkontakte/certs:ca` → `/app/vkontakte/ca.crt`)
  не содержит HARICA-рута → Node mTLS-клиент падает.
  Воспроизведено: `openssl s_client -CAfile ~/.mccloud/ca.crt` → verify code 20;
  `curl -k --cert/--key` → PMS API 200.
- Косвенно: infra delete_cluster-ы 25–26.08 через тот же хост проходят (CA infra доверяет).
- Прод-деплой: `backstage-nodejs.backstage-front` (ns dzen), image `zen-backstage:5aba0546`
  (21.08). Дефолт vkontakte pms.baseUrl в шаблоне репо = `https://conf.vkcl.ru` (с Feb 2025),
  PMS-переменная `mdb.vkontakte.pms.baseUrl` пуста — но в ошибке `pms.cloud.vk.team`,
  т.е. в задеплоенном образе дефолт другой (проверить на хосте не удалось: ssh 403,
  mcc logs Forbidden на очередь).

## Рекомендации (в комментарии тикета)

1. Инфраструктуре: добавить HARICA root в vkontakte CA-бандл в vault + рестарт сервиса,
   либо перевести vkontakte обратно на conf.vkcl.ru.
2. После фикса — retry операции.
3. Dev-тикет: не маскировать TLS/сетевые ошибки под 404 в doRequestWithRequestInfo.

## Грабли сессии

- `mcc ssh/sshexec/logs` на front-хосте backstage → 403 Forbidden (нет прав на очередь
  `backstage-front.app.production.front.prod`) — конфиг с хоста не прочитать.
- PMS `conf/values.do` по `mdb.vkontakte.pms.baseUrl` пуст во ВСЕХ ns × application —
  пустой ответ не означает «переменной нет в нужном месте», просто проверили широкий набор.
- Один и тот же operationId ретраями даёт разные тексты ошибок (401 ACCESS_DENIED для
  ok-pyvault SA n.dergunov, затем TLS 404) — не искать «смену ошибки», это ретраи одной операции.
