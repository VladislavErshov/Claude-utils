# MDBSUP-4841 — Помочь сервису авторизоваться в Kafka (2026-08-27, ожидаем пояснений)

## Суть тикета

Vector (контейнер vk-games-base, канаря `1.shard0-java.canary-vk-games-base.hc.idzn.ru`)
не может авторизоваться в Kafka юзером `vk-games-new-features-recommender`
(SCRAM-SHA-256, invalid credentials). Креды созданы через UI MDB, per one-cloud
«корректно подсасываются бэкендом».

## Диагноз

Проблема не на стороне MDB. Vector на канаре указывает на **чужой кластер**
(`others-recommender-kafka:9092`), где этого юзера не существует → SCRAM invalid
credentials. На целевом кластере `logs-recom-wizard-kafka` креды рабочие
(проверено подключением).

Фикс для команды vk-games-base (vector-features.toml):
- bootstrap: `1.broker.logs-recom-wizard-kafka.<dc>.wan.idzn.ru:9093` (порт 9093, `.wan.`)
- остальное у них уже верно: SASL_SSL + SCRAM-SHA-256 + `broker.address.family=v6`
  + CA `/etc/zen/cacerts/tls-ca.crt` + `tls.verify_hostname=false`

## Грабли этой сессии

- `mcc -n dzen` без `--local`/`-c` падал EntityNotFoundException по `.wan.idzn.ru` FQDN;
  реальное имя инстанса — без `.wan.` (`mcc --local -n dzen -c pc instances "%...%"`).
- Канарю `1.shard0-java.canary-vk-games-base.hc.idzn.ru` напрямую зайти не удалось
  (websocket 403) — конфиг vector взят со скриншота из тикета.
- `kafka-configs.sh --describe --entity-type users` не печатает `User:` — grep по
  `user-principal`. На idzn-брокерах клиент ходить на `localhost` не может (SAN),
  только на свой FQDN.
- Пароль в sshexec-командах маскируется mcc-ом как `__SECRET_N__` — но в файл на
  хосте пишется реально; после проверки файлы /tmp/u-scram.properties на
  1.broker.logs-recom-wizard-kafka.pc.idzn.ru стоит удалить.
