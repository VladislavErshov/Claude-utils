# MDBSUP-5237 — kafka-news-snapshots: CC add_broker падает, брокер 21004 не публикует BROKER_CPU_UTIL

- **Кластер:** `9974b16f-f2d1-4b29-a237-a9753d1f3700` (kafka-news-snapshots-news-kafka, кросс-ДЦ 4×4: hc/kc/pc/ec)
- **Симптом:** `NotEnoughValidWindowsException` (0 valid windows) при add_broker; в логах CC каждые ~2 мин «Skip generating metric sample for broker 21004 … [BROKER_CPU_UTIL]», 37 партиций скипаются.
- **Диагностика:**
  - 21004 = `4.broker.kafka-news-snapshots-news-kafka.kc.one-infra.ru` (ДЦ kc). Внимание: kc/pc/ec хосты в mcc не видны из namespace `infra` — нужны `--cloud kc/pc/ec` (`mcc --cloud kc sshexec -n infra …`).
  - Брокер жив (порт 9092 открыт, зарегистрирован в кластере), но CruiseControlMetricsReporter каждую минуту: `Failed reporting CPU util. → java.io.IOException: Java Virtual Machine recent CPU usage is not available.` → BROKER_CPU_UTIL не публикуется.
  - Jolokia на 21004: `java.lang:type=OperatingSystem → ProcessCpuLoad/SystemCpuLoad = -1.0` (на здоровом kc-1 = 0.0). Состояние пережило рестарт брокера — уровень контейнера, не процесса.
  - JVM считает CPU load через cgroup v1 контейнера (`ContainerCpuTicks.getContainerCpuLoad`, тестовая JVM падала NPE в `CgroupV1Subsystem.getCpuQuota`). На kc-4: cgroup cpu quota = -1 (unlimited), cpuacct.usage тикает, /proc/self/stat тикает, ядро и JDK (17.0.15, одинаковый build) идентичны здоровым хостам → сломано внутри контейнерного окружения porto/lxcfs на kc-4, воспроизводится свежей JVM. Uptime хоста 427 дней.
- **Арифметика блокера:** 16 брокеров, `min.valid.entity.ratio` не задан (дефолт 0.95); 15/16 = 0.9375 < 0.95 → 0 валидных окон, CC полностью заблокирован. В конфиге CC задан только `min.valid.partition.ratio=0.95`.
- **Что сделали:** хост kc-4 отправлен на миграцию (владелец — Владислав), 08.09.2026.
- **Запасной вариант (не применялся):** `min.valid.entity.ratio=0.9` в cruisecontrol.properties + рестарт CC — разблокировал бы add_broker при одном битом брокере.
- **Грабли:** kafka CLI на брокерах требует `--command-config /opt/kafka/config/client.properties` и FQDN вместо localhost (SASL_SSL, сертификат не матчится на localhost); логи брокера — `/mnt/logs/dbms/kafka-broker.out.log`; «Error: non zero exit code: 1: OCI runtime error» от sshexec при exit≠0 команды (например `grep -c` без совпадений) — не ошибка сессии.
