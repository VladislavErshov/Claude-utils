# Confluence Writer

Скилл для работы со страницами Confluence через MCP (сервер `generic_confluence`). Используй, когда нужно создать, отредактировать или привести в порядок страницу Confluence — особенно регламенты/DRP-страницы команды MDB.

## Рабочий процесс

1. **Прочитай цель страницы.** `confluence_get_page` (+ `confluence_get_page_source` для storage-формата). Для регламентных страниц команды MDB ориентируйся на сестринские страницы (например, «План действий для ZooKeeper» 2123659507, «План действий для ClickHouse» 2126595643) — единая структура: панель «Связанные страницы» → TOC → «Общие сведения» → «Регламент действий» с нумерованными шагами → справочные разделы → «Необходимые доработки».
2. **Проверь inline-комментарии** (`confluence_get_inline_comments`) ДО правки. Все `<ac:inline-comment-marker ac:ref="...">` из storage-формата обязаны сохраниться в новой версии — иначе комментарии станут dangling.
3. **Мелкие правки — `confluence_update_page_section`** (с обязательным `confluence_preview_section_update` перед применением). Крупная реструктуризация — `confluence_update_page` полным body.
4. **После правки проверь результат**: `confluence_get_page` c `start_index` (export-view короче storage) + повторный `confluence_get_inline_comments`.
5. **Запиши таску в историю**: `HISTORY.md` в папке этого скилла (формат — см. файл).

## Технические грабли MCP (выучено на практике)

- **Маркеры без HTML-тегов не находятся**: текст без тегов оборачивается в `<p>...</p>`. Включай в маркер тег: `<strong>`, `</li>`, `</p>`, `<h2>`, `<code>`.
- **`<placeholder>` вида `<topic-name>` внутри CDATA код-макроса ломает HTML-валидацию** («HTML structure validation failed», правка молча НЕ применяется). В код-блоках пиши плейсхолдеры без угловых скобок: `TOPIC_NAME`.
- **Крупные вставки с несколькими макросами** (code + warning в одном content) стабильно валят валидацию. Вставляй кусками: текст → таблица → макросы; дубли от промежуточных вставок удаляй пустым content между уникальными маркерами.
- **start_text == end_text не поддерживается**; при последовательных вставках после одного якоря контент дублируется — проверяй и чисти.
- **Параллельные правки одной страницы дают 409** (конфликт версий). Правки страницы — строго последовательно; при 409 просто повтори вызов.
- **Правка не применилась молча** — подозревай валидацию; всегда проверяй результат чтением.
- Таблицы без `<thead>` (просто `<tbody>` с `<th>` в первой строке) проходят надёжнее.
- **Страница-легаси валит валидатор на ЛЮБУЮ секционную правку** (несбалансированный исходный HTML: span-суп, незакрытые `<pre>` в `<li>`) → секционный путь закрыт. Решение: полная перезапись через REST API напрямую (креды MCP-сервера лежат в `~/.config/opencode/opencode.json` → mcp/generic:confluence/environment: CONFLUENCE_URL + CONFLUENCE_TOKEN, авторизация `Authorization: Bearer`):
  1. `GET /rest/api/content/{id}?expand=body.storage,version` — сверить body с подготовленным оригиналом (байт-в-байт).
  2. Трансформация офлайн python-скриптом (заголовки regex-ом, панель) + верификация: текст без тегов заголовков идентичен оригиналу, счётчики code-макросов/CDATA/li/inline-markers сошлись.
  3. `PUT /rest/api/content/{id}` с version+1 и body из файла (`-d @payload.json`).
  4. Re-fetch + difflib-сверка с целевым файлом; единственное допустимое расхождение — сервер добавляет `ac:macro-id` новым макросам.
- Перед украшением старой страницы — пробная мелкая секционная правка; валидатор валит → сразу REST-путь, не тратить попытки.
- **Нормализация заголовков легаси — только с учётом контекста, не по тегу.** На этой странице один и тот же тег h4 использован и как ребёнок h2-секции («Не могу подключиться»), и как ребёнок h3 («Создание» под «Пользователи»). Механическое h4→h2 сплющивает вторые в один уровень с родителями. Правило: при обходе заголовков подряд трекать «виден ли h3 после последнего h2» — такие h4 отображаются на уровень ниже остальных; h5 — на уровень ниже своего h4-родителя. После перезаписки всегда выводить итоговое дерево заголовков (python-список с отступами) и смотреть глазами.

## Стиль документов

Текст страниц писать **через скилл `text-writer`** (раздел Confluence) — там агрегирован
стиль: формальный тон, заголовки, безличные конструкции, запрет слова «оператор» и др.
Этот скилл отвечает только за доставку (MCP, структура, секционные правки).

- Пользовательская дока живёт в git-репозитории `mdb-docs` (рядом с проектами в ~/Documents/Git/). Если правится Confluence-регламент, проверь парную страницу в mdb-docs — синхронизируй обе.
