### Дополнение 2026-08-21 (позднее) — стиль по замечаниям пользователя (страница 2140342410)

**Новые правила стиля (перенесены в SKILL.md п.7–11):**
- Не «оператор» (в MDB это внутренний проект) — безличные конструкции: «stray-папки переименовываются», «скачать локально».
- Не «дежурная смена/команда» — «для дежурных».
- В описании метода — инфинитивы/пассив, без указания исполнителя: «Docker-образ переключается через изменение манифеста хоста» (убрано «пользователем»).
- Ссылка на скилл /kafka-downgrade-4.3-to-3.8 — на GitHub (https://github.com/VladislavErshov/Claude-utils).
- «Снимок для восстановления собирается на любом брокере» вместо «на любом брокере собрать снимок».

**Технический урок (важно!):** если в content секционной правки ДУБЛИРОВАТЬ текст start-маркера — маркер сохраняется и content вставляется рядом → дубли текста. Content должен содержать ТОЛЬКО то, что встанет между маркерами. Дополнительно: content-фрагменты без начального HTML-тега враппер оборачивает в `<p>` и рвёт абзац — при точечных правках середины абзаца безопаснее перезаписывать весь абзац/панель целиком одним content, начинающимся с `<p>`.

## 2026-08-21 (завершение) — финальная правка стиля «Переход на 4.3 и обратный откат» (MDB, pageId=2140342410)

**Задача.** Довести страницу отката Kafka 4.3 → 3.8 до стилевых требований пользователя после первичной реструктуризации.

**Сделано (v6 → v26):**
- «дежурная смена/команда» → «для дежурных» (заголовок h1 инструкции + «Назначение документа»).
- Убрано слово «оператор» (в контексте MDB это внутренний проект): «Оператор переименовывает stray-папки...» → «Stray-папки переименовываются обратно...», «скачать на машину оператора» → «скачать локально».
- Описание метода переведено на безличные конструкции без указания исполнителя: «Docker-образ переключается пользователем» → «Docker-образ переключается через изменение манифеста хоста в админке облака» (и в «Ключевых технических решениях», и в этапе 2).
- Этап 0: «На любом брокере собрать снимок» → «Снимок для восстановления собирается на любом брокере».
- Ссылки на скилл-исполнитель /kafka-downgrade-4.3-to-3.8 сделаны ссылками на GitHub (https://github.com/VladislavErshov/Claude-utils) — в панели «Связанные страницы и материалы» и в note перед инструкцией.

**Грабли этой итерации (важно для будущих правок):**
- Инкрементальные секционные правки середины абзацев многократно рассыпались на `<p>`-фрагменты и плодили дубли (маркер сохраняется, content встаёт рядом). Итоговое правило: точечную правку абзаца/панели делать одним content — перезаписью всего блока от `<p>` (или `<h2>`/`<ac:rich-text-body>`) до закрывающего тега; после каждой правки сверять export-view.
- Пустой content между маркерами (`start_text` уникальный, `end_text` — начало следующего блока) — рабочий способ удалять дубли/пустые `<p />`.
- CDATA-иммунитет подтвердился: содержимое код-макросов секционными маркерами не трогается.

**Результат:** страница в целевой структуре «описание метода → инструкция для дежурных» (этапы 0–9, чек-лист, возможные ошибки), стилевые требования пользователя выполнены и закреплены в SKILL.md (п.7–11).

**Что сделал до блокировки:**
- Собрал полный storage (70КБ) в файл, офлайн-скриптом подготовил и побайтно верифицировал трансформацию (текст без тегов заголовков идентичен оригиналу; счётчики код-макросов/ссылок/li/CDATA сошлись; inline-маркер сохранён).
- Попытки применить (7 шт., все отклонены валидатором, версия осталась 108, данные целы): panel-макрос, info-макрос, простой <p> со ссылками, одиночная замена h2→h1.

**Причина блокировки:** секционный валидатор MCP проверяет весь результирующий storage; страница — легаси с несбалансированным HTML (span-суп, незакрытые <pre> в <li>, вложенные <p>, TOC в <h3>). Любое непустое изменение = fail.

**Пути доведения (не выполнено):** (а) вручную в UI Confluence по подготовленному списку правок — панель после заголовка «Разборки Kafka», 7× h2→h1; (б) полная перезапись update_page с воспроизведением всего body и обязательной пост-проверкой (re-fetch + diff с подготовленным файлом /tmp/kafka_page_new.html).

**Уроки:**
- Перед «украсить» старую страницу — сперва пробная мелкая секционная правка; если валидатор валит — STOP, предлагать UI/полную перезапись с верификацией.
- Полный оригинал storage недоступен в контексте (тул-вывод обрезается в чате, полный — только в файле тул-вывода) — полная перезапись «из головы» невозможна и опасна.
- Офлайн-подготовка трансформации с difflib/счётчиками — правильный паттерн верификации «ничего не потеряно».
