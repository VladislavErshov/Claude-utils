# Стиль descriptions на русском

Правила написания `description` для Grafana-панелей.

## Жёсткие правила

1. **Переносы строк — двойной `\n\n`.** Grafana рендерит переносы только если между абзацами есть пустая строка. Одиночный `\n` игнорируется (склеивается в одну строку). Если нужна структура с абзацами — ставь `\n\n` между ними. Если короткое описание — пиши одной строкой, без `\n` вообще.

   ❌ `"Метрика X.\nЧто смотреть: пункт 1"` (одиночный `\n` — Grafana склеит)
   ✅ `"Метрика X.\n\nЧто смотреть: пункт 1, пункт 2."` (двойной `\n\n` — будет два абзаца)
   ✅ `"Метрика X. Что смотреть: пункт 1, пункт 2."` (одной строкой — тоже работает)

2. **Без описания расчёта.** Не писать как метрика считается — `rate(...[$__rate_interval])`, `sum by`, `group_left`, `60 ×`. Это детали реализации, пользователь видит их в PromQL-редакторе.

   ❌ `"Метрика выводится в минуту: 60 × rate(...[$__rate_interval])"`
   ✅ (просто убрать это предложение)

3. **Без глаголов-повелительных.** Не "смотри", "проверь", "используй". Просто описание что на графике и что значит.

   ❌ `"Смотри на растущий Reject — консьюмер падает"`
   ✅ `"Растущий Reject — консьюмер падает на обработке"`

4. **На русском.** Не оставлять английские описания от оригинального дашборда если переводишь.

## Структура хорошего description

`<что показывает>. <что значит норма>. <что значит проблема>.`

Примеры:

- `"Суммарный лаг по консьюмер-группе (обычные и share groups) и топику."` — короткий, без что-смотреть, если метрика простая.

- `"Лаг по конкретной партиции консьюмер-группы (обычные и share groups). Лаг на одной партиции — горячая партиция, медленный консьюмер или задержки на конкретном брокере."` — что показывает + что значит аномалия.

- `"Состояние share-групп, количество участников и in-flight сообщений. State=Stable — норма, State=Dead или долгий PreparingRebalance — проблема с консьюмером, Members=0 при работающем консьюмере — консьюмер не зарегистрировался, In-flight messages растёт — консьюмер не успевает ack-ать."` — что показывает + несколько маркеров аномалий через запятую.

## Когда description не нужен

Если title панели самодокументирующий (например "Brokers Online", "Active Controllers"), description можно оставить пустым. Не плодить очевидные `"Number of brokers online."`.

## Где хранить «что смотреть»

Если хочется сохранить детали («что смотреть», «нормальные значения», «типичные причины») — это идёт в комментарий в самом PromQL или в документацию, не в description. Description в Grafana tooltip при наведении — должен быть коротким.

## Чек-лист перед сохранением

- [ ] Одной строкой, нет `\n`
- [ ] Нет формул расчёта (`rate`, `sum by`, `$__rate_interval`)
- [ ] Нет глаголов-повелительных
- [ ] На русском
- [ ] Не дублирует title
