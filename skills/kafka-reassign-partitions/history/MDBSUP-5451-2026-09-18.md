# extdbpu-oneme-kafka: рецидив URP из-за мёртвых реплик выведенного ДЦ (MDBSUP-5451)

**Дата:** 2026-09-18
**Кластер:** `extdbpu-oneme-kafka` (infra, 255 брокеров: kc=21xxx, pc=22xxx, ec=23xxx)
**Тикет:** MDBSUP-5451 (66 партиций UnderReplicated в мониторинге, critical)
**Прецедент:** [MDBSUP-4994](2026-09-02_extdbpu-oneme-kafka-dead-dc-replicas.md) — **тот же кластер** 16 днями ранее
(67 партиций, диапазон 20033–20133). Здесь рецидив: 102 партиции, диапазон 20050–20129, **другие топики**
(oneme_core_AdPixels, ChannelMessageRecomEvents, PollEvents, QueryLinksEvents). Схема diagnose/fix — та же,
ниже только отличия и новые грабли.

## Отличия от MDBSUP-4994

- Объём: 102 URP-партиции, перенос ~420 ГБ (kafka-log-dirs --describe), максимум 9.5 ГБ на партицию.
- Замены: ghost → недостающий ДЦ round-robin 1–85, итог 34 kc / 34 pc / 34 ec, лидеры сохранены.
- После execute хвост: 12 партиций PushEvents/userReadMarks/OnemeCallsEvents выпали из ISR
  по брокеру 21058 (58.broker.kc, load avg 38 — лидер части переносимых партиций обслуживал
  синхронизацию новых реплик). Транзиент — разошлось само за ~15 мин, трогать не нужно.

## Новые грабли

1. **`--execute --throttle N` при мёртвых брокерах в assignment — гарантированный фейл, ретраи бессмысленны.**
   `TimeoutException: Timed out waiting for a node assignment. Call: incrementalAlterConfigs`:
   throttle-шаг строит broker-level конфиги из текущего assignment (где есть несуществующие 20xxx),
   AdminClient не может смаршрутизировать вызов на незарегистрированные ноды. Увеличенные таймауты
   (request.timeout.ms=180000, default.api.timeout.ms=600000 в клиентском конфиге) НЕ помогают —
   причина структурная. Рабочий путь: `--execute` без `--throttle` (шаг incrementalAlterConfigs не
   вызывается вовсе), при большом объёме — выставлять throttle вручную на живых брокеров до execute.
2. **CC API порт**: webserver 8080 (`webserver.http.port=8080` в cruisecontrol.properties), 9090 не слушается,
   9000 — другой java-порт. `GET /kafkacruisecontrol/state?substates=executor` → NO_TASK_IN_PROGRESS.
3. mcc scp при заливке reassign.json снова молча не залил — base64-чанками через expect
   (канон mcc-host-worker/commands/scp.md, 32 чанка на 18.6 КБ, сверка wc -c).
4. `--verify` при частичном накате throttle-конфигов сам их чистит («Clearing broker-level/topic-level
   throttles») — отдельная зачистка не нужна.

## Вывод по продукту

Удаление ДЦ (delete_hosts) систематически покрывает reassign не все партиции: extdbpu стрельнул дважды
(4994 → 5451, другие топики), плюс extdbpr/extdbperf ([2026-09-08](2026-09-08_extdbpr-extdbperf-oneme-kafka-dead-dc-replicas.md))
и MDBSUP-5159. Паттерн «URP не сходит → в Replicas 20xxx» на oneme-кластерах = искать мёртвый ДЦ, фикс
реассигном, и заводить баг на покрытие reassign'ом всех партиций при delete_hosts.
