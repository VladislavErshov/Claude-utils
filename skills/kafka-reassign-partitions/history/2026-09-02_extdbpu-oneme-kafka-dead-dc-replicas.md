# extdbpu-oneme-kafka: хронический URP из-за мёртвых реплик выведенного ДЦ (MDBSUP-4994)

**Дата:** 2026-09-02
**Кластер:** `extdbpu-oneme-kafka` (infra, 255 брокеров: pc=22xxx, kc=21xxx, ec=23xxx; ДЦ-маппинг
определён чтением node.id на 1.broker каждого ДЦ)
**Тикет:** MDBSUP-4994 (URP-алерт в UI, «какие топики и почему», нагрузки нет)

## Диагноз

- `--describe --under-replicated-partitions` → 67 партиций, и в **каждой** из ISR выпал
  брокер диапазона **20xxx** (20033–20133). Лидеры живые (21/22/23xxx), Leader: none = 0.
- `kafka-broker-api-versions.sh` → зарегистрировано 255 id, **ни одного 20xxx** —
  диапазон принадлежит выведенному ДЦ. Полный describe: 2786 партиций, с 20xxx ровно те же 67.
- Причина: при выводе ДЦ 4 топика не попали в reassign → мёртвая реплика вечно вне ISR →
  перманентный URP. Тот же паттерн, что [MDBSUP-4166](MDBSUP-4166.md) (там 23 партиции одного мёртвого брокера,
  здесь — 52 мёртвых id из целого ДЦ).

## Фикс

1. Пул живых id → `/tmp/ids.txt` (из api-versions), полная карта → `/tmp/oneme_full.txt`.
2. Генерация python'ом на хосте: для каждой из 67 партиций мёртвый 20xxx заменяется
   in-place на least-loaded живого брокера **недостающего ДЦ** из оставшихся двух реплик
   (итоговый спред kc/pc/ec = 67/67/67, RF=3, порядок/preferred leader сохранены).
3. `--execute --throttle 104857600` → **TimeoutException: incrementalAlterConfigs**
   (третий кластер подряд с этой граблёй — похоже, системная, а не разовая).
   `--execute` без throttle → started; verify через 10с: **completed 67/67** (данные
   events-партиций лёгкие, синхронизация мгновенная).
4. Финал: URP=0, unavailable=0, 20xxx в Replicas: 0/2786, ISR полные.

## Грабли

- Заливка двух файлов одной expect-строкой (два base64-блоба в одном send) — молча
  портится (python упал, json не создан, exec «Unable to read file»). Заливать по одному
  файлу за заход.
- Маппинг «ДЦ → диапазон id» у этого кластера нестандартный (4 диапазона на 3 живых ДЦ,
  20xxx — призрак прошлого ДЦ): определять чтением `node.id` на 1.broker каждого ДЦ
  и списком зарегистрированных id, не по таблице из SKILL.md.
