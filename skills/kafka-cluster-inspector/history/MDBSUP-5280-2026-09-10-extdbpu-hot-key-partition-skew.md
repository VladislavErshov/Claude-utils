# MDBSUP-5280 — extdbpu: «аномальный» размер партиции 35 oneme_core_NetBackEvents (~1 ТБ)

Дата: 2026-09-10. Kafka, ns infra, кластер `94bed650-7adf-4b78-9640-37a311033e65`
(`extdbpu`, project 73, criticality A). 85 брокеров × 3 ДЦ (ec/kc/pc) + 3 контроллера,
cruise в pc. Автор тикета видел в CC UI (Kafka Partition Load) Disk=1020575 MB у
партиции 35 и счёл значение некорректным («диск не переполняется»).

## Вывод: метрика CC корректна, партиция реально ~1 ТБ

- Факт с диска (`kafka-log-dirs.sh` через брокер): 22046 (46.broker.pc, лидер)
  1047.98 GB, 21037 (37.broker.kc) 1046.91 GB, 23040 (40.broker.ec) 1046.91 GB —
  реплики консистентны.
- Топик 480 партиций: медиана 79 GB, p90 80 GB, второе место 101 GB → партиция 35
  в 13× от медианы. Перекос именно в данных, не в репликации.
- Ретеншн (`retention.ms=216000000` = 60 ч, segment 1 GB) работает: старейший
  .log на лидере датирован ровно границей 60 ч. Размер стабилен, диску ничего не
  грозит — в окно ретеншена партиция принимает ~1.5 млрд msg (~7000 msg/s,
  avg value ~550-700 B).

## Корневая причина: горячий ключ `0x0000000000000000`

Сэмпл 2118 сообщений из партиции 35 (console-consumer от earliest, ключи хэшировал
md5): **1837 (87%) с одним ключом = 8 нулевых байт** (`\x00`×8), следующий ключ —
17 сообщений. Это дефолтный/unset int64 (или byte[8]) в сериализации продюсера.
murmur2(нули) % 480 → всегда партиция 35. ~90% объёма партиции — трафик этого ключа.

Не баг продукта MDB и не инфраструктура — данные клиента. Никаких правок в кластере
не требуется.

## Рекомендации (для ответа в тикет)

1. Метрика корректна; диск не переполнится — ретеншн держит ~1 ТБ на каждой из
   3 реплик стабильно.
2. Реальный риск — перекос нагрузки: лидер 22046 держит весь fetch/produce этой
   партиции (CPU/сеть).
3. Фикс на стороне продюсера: не писать нулевой/дефолтный ключ (реальный ID или
   `null` → sticky-партишинер распределит сам), либо солить ключ.
4. Увеличение числа партиций НЕ поможет — тот же ключ уйдёт в одну партицию.

## Грабли инструментов (Kafka 3.8, образ MDB)

- `kafka-log-dirs.sh` пишет INFO-логи **в stdout** до JSON-строки — парсить поиском
  строки с `{`, не `json.load(stdin)`.
- `-command-config` у admin-тулов есть, но у **console-consumer** флаг называется
  `--consumer.config` (через точку); `--consumer-config`/`--command-config` → usage.
- Подключение `localhost:9092` из-под брокера с SASL_SSL падает
  `SSL handshake: checkServerTrusted` (сертификат не для localhost) — ходить на FQDN
  хоста: `46.broker.<cluster>.pc.one-infra.ru:9092`.
- `kafka-broker-api-versions.sh` формат строк: `host:9092 (id: 22046 rack: pc)` —
  grep по `(id: 22046)\b`; grep без совпадений роняет sshexec (exit 1) — добавлять `; true`.
- ID брокеров кластера extdbpu: pc=22000+, kc=21000+, ec=23000+ (не как в таблице
  SKILL.md по умолчанию — код ДЦ кластер-специфичен, проверять describeCluster'ом).
