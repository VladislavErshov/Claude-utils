# MDBSUP-5279 — переполнение диска брокера kc: stray-папки + утёкшие fd (rm не освобождает место)

Дата: 2026-09-10
Тикет: https://jira.vk.team/browse/MDBSUP-5279
Кластер: oneme kafka (`94bed650-7adf-4b78-9640-37a311033e65`), KRaft
Хост: `57.broker.extdbpu-oneme-kafka.kc.one-infra.ru` (broker.id=21057)
Канон: wiki «Дежурство MDB: Kafka» → «Кончилось место на брокерах»
(`commands/troubleshooting.md`), паттерн чистки — MDBSUP-5179.

## Симптом

Диск `/mnt/data` брокера 21057 — 90% (2.7T/3.0T). CC-балансировка по дефолтным
целям запущена, но нагрузку на инстанс не снижает. Брокер жив.

## Диагностика

1. `du -sk /mnt/data/log/* | sort -rn | head` — ~868 ГБ занимают 6 `-stray`-папок
   от 25.08 (16 дней): NavigationEvents-56 (~339G), -59 (~260G), PushEvents-295
   (~97G), -42 (~66G), -174 (~65G), -21 (~41G). Живые партиции тех же разделов
   на брокере есть (NavigationEvents-56/59, PushEvents-42 подтверждены).
2. Почему CC не помогает: stray-копии не входят в assignment брокера и не видны
   балансировщику — он крутит живые партиции, а место занято осиротевшими копиями.
3. `rm -rf *-stray` освободил только ~59 ГБ (90% → 88%) вместо ~868 ГБ →
   `lsof -nP +L1` показал **834 deleted-but-open файла = 830 ГБ**: kafka-broker
   (pid 149552) держит утёкшие fd на сегменты stray-папок с 25.08 (rename в
   `-stray` при старте брокера не закрыл хэндлы). Пока fd открыты, место не
   освобождается — классика I49678 (cruise-control.out.log), но на data-сегментах.

## Фикс

1. `rm -rf /mnt/data/log/*-stray` (канон wiki).
2. `systemctl restart kafka-broker` через sshexec — прошёл без `OCI runtime
   error: 129` (грабля MDBSUP-5179 здесь не выстрелила).
3. Верификация: `is-active=active`, старый pid исчез, `lsof +L1` deleted-fd = 0,
   `/mnt/data` 90% → **61%** (свободно 1.2T), в логе маркеры
   `Successfully registered broker 21057` + `Kafka Server started`.

Альтернатива без простоя (пользователь выбрал рестарт): обнулить утёкшие fd
через `/proc/<pid>/fd/*` по маске `*-stray*(deleted)` — тот же приём, что
`truncate -s 0 /proc/<pid>/fd/N` в I49678.

## Корень

Reassign 25.08 увёл партиции с брокера; при последовавшем рестарте брокер
переименовал старые копии в `-stray`, но не закрыл их fd. CC-балансировка место
не освобождает (stray не в assignment). Без чистки диск доехал бы до 100%.

## Грабли / новые уроки

1. **После `rm -rf *-stray` всегда проверять `lsof -nP +L1`**: df может
   сдвинуться лишь на часть места — хвост держат утёкшие fd брокера на
   deleted-файлы. Освобождение — рестарт kafka-broker либо truncate через
   `/proc/<pid>/fd`.
2. `du -sk` по папкам ≠ освобождённое место по `df` — сверять именно df после rm.
3. Стрей-папки могут месяцами лежать незамеченными, пока диск ползёт к 100% —
   на переполненном брокере их искать первыми (`ls -d /mnt/data/log/*-stray`).

## Итог

Диск 61%, брокер зарегистрировался, тикет закрыт с комментарием (результат +
причина, почему ребаланс не помогал). Дополнение внесено в
`commands/troubleshooting.md` (секция про `-stray`).
