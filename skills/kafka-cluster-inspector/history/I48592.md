# I48592 — Controllers в crash-loop: node.id-свалка из-за неверного kafka.layout в PMS (eventstream-general-adtech-kafka)

Дата: 2026-08-24.

## Итог

**Корневая причина — в PMS: `kafka.layout` противоречил `kafka.controller.quorum`.**
Пользователь исправил PMS — после этого всё заработало. Вайп дисков помогал лишь
частично/временно, потому что confp при каждом рендере заново вычислял неверный node.id.

## Механика бага

`node.id` контроллера рендерится в `controller.properties.j2` по формуле:

```jinja
{% set dc_id = pms('kafka.layout').split(',').index(env('cloud_name')) %}
{% set instance_id = env('cloud_hostname').split('.')[0]|int %}
node.id = 10000 + dc_id*1000 + instance_id
```

т.е. **node.id зависит от ПОЗИЦИИ ДЦ в списке `kafka.layout`**. На момент инцидента:

| PMS-переменная | Значение | Что даёт |
|---|---|---|
| `kafka.layout` (сломанный) | `pc,rc,ec` | pc→10001, rc→**11001**, ec→**12001** |
| `kafka.controller.quorum` | `14001@ec, 11001@pc, 12001@rc` | pc=11001, rc=**12001**, ec=**14001** |

Layout был изменён (в нём исчезли ДЦ — старая раскладка имела pc@1, rc@2, ec@4:
брокер ec рендерился с node.id=24001). Voters при этом не менялись. Итог — каждый
новый рендер конфига выдаёт node.id, не совпадающий ни с voters, ни с meta.properties
на диске.

## Развитие инцидента

1. **ec**: контроллер падал `Stored node id 14001 doesn't match previous node id 12001
   in /mnt/data/log/meta.properties` (диск=14001, конфиг=12001).
   «Фикс» вайпом `/mnt/data/log`+`/mnt/data/metadata` + рестарт хоста — сервис стал
   active, **но это зомби**: нода поднялась с id 12001 (слот rc), в кворум не входит.
2. **rc**: та же болезнь, другая стадия — конфиг рендерил 11001 (id pc!), диск после
   вайпа принимал этот id, нода старта с epoch 1 и падала:
   `IllegalStateException: leader pc (id: 11001) epoch 2361 inconsistent with current
   leader empty and epoch 1` — дубликат id в кворуме невозможен.
   **Вайп на rc НЕ помог** — confp при старте снова отрендерил неверный 11001.
3. **pc** — единственный живой voter (лидер, epoch 2361). Кворум фактически 1/3.

## Финальный фикс (сделал пользователь)

Исправить `kafka.layout` в PMS (вернуть раскладку, соответствующую
`kafka.controller.quorum`: pc@1, rc@2, ec@4 — с учётом всех ДЦ кластера), затем
confp-рендер + вайп данных на сломанных контроллерах → контроллеры поднялись со
своими правильными id (11001@pc, 12001@rc, 14001@ec) и вошли в кворум.

## Выводы / грабли

- **`kafka.layout` и `kafka.controller.quorum` обязаны быть согласованы**: node.id —
  производная от позиции ДЦ в layout. Сверять при любом изменении layout: пересчитать
  `10000 + index*1000 + 1` для каждого ДЦ и сравнить с id в voters.
- **Вайп диска маскирует, но не чинит**: если неверен PMS, confp снова отрендерит
  неверный node.id после вайпа. Вайп помогает только когда PMS уже корректен, а конфликт
  «диск vs конфиг» — наследие прошлого.
- **«Active» после вайпа ≠ «в кворуме»**: ec выглядел живым (active) с чужим id.
  Проверять не systemctl, а `kafka-metadata-quorum.sh describe --replication` с живого
  voter'а.
- **Бомба при сломанном layout**: любой рестарт брокера отрендерит node.id по новой
  формуле (24001→22001) → брокер зарегистрируется как новая нода, реплики уйдут в
  under-replicated. Пока layout не исправлен — брокеры не рестартовать.
- Симптом-маркеры: `Stored node id X doesn't match previous node id Y` (конфликт диск vs
  конфиг) vs `leader ... epoch N inconsistent with current leader empty and epoch 1`
  (дубликат id — этот node.id уже занят другим voter'ом).

## Порядок диагностики (повторяемый)

1. `systemctl is-active kafka-controller` + `tail kafka-controller.out.log` в
   `/mnt/logs/dbms/` на всех трёх контроллерах.
2. Сверить на каждом: `node.id` в `/opt/kafka/config/controller.properties`,
   `node.id` в `/mnt/data/{log,metadata}/meta.properties`, ожидаемый id из
   `controller.quorum.voters`.
3. Прочитать PMS: `kafka.layout` и `kafka.controller.quorum` (pms-read.sh / values.do),
   пересчитать формулу node.id для каждого ДЦ — найти рассинхрон.
4. Фиксить PMS → confp → (при необходимости) вайп данных контроллера → старт.
