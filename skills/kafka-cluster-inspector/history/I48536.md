# I48536: ozon-products-events-adtech-kafka — under min ISR на ozon_s2s_events-292 (битый лог лидера)

**Дата**: 2026-08-24
**Кластер**: `ozon-products-events-adtech-kafka` (брокеры kc=200xx, pc=210xx, rc=220xx; 8 на ДЦ)
**Хост входа**: `1.broker.ozon-products-events-adtech-kafka.kc.one-infra.ru`

## Симптом

1. Grafana: 57 партиций "at min ISR" + 1 партиция "under min ISR".
2. `--at-min-isr-partitions`: 57 партиций `ozon_s2s_events` без брокера 22006 в ISR —
   брокер `6.broker...rc` (22006) был остановлен (graceful shutdown в 17:33, руками/lifecycle).
3. `--under-min-isr-partitions`: единственная `ozon_s2s_events-292`
   (`Replicas: 20003,22002,21002`, `Isr: 22002` — только лидер, min.insync.replicas=2).

## Диагностика

На фолловерах 20003 (и 21002) — вечный цикл с 17:19:

```
ERROR [ReplicaFetcherThread-0-22002] Unexpected error ... partition ozon_s2s_events-292 at offset 5806837213
kafka.common.OffsetsOutOfOrderException: Out of order offsets found in append
WARN Partition ozon_s2s_events-292 marked as failed
```

Ключевой вывод сделан после вайпа реплики на 20003: реплика пересоздалась с нуля,
корректно догнала ~76 млн записей до 5806840390 — и **снова** упала с той же ошибкой.
→ Дивергенция не на фолловерах, а **в логе лидера 22002** (офсеты идут не по порядку,
следствие старого unclean election). Вайпы фолловеров бесполезны.

## Фикс (unclean перевыборы, прошли почти без потерь)

1. `systemctl stop kafka-broker` на лидере `2.broker...rc` (22002).
2. Unclean election (по доке Дежурство MDB: Kafka — флаг `--admin.config`, НЕ `--command-config`!):
   ```
   export HEAP_OPTS="-Xmx512m"
   /opt/kafka/bin/kafka-leader-election.sh --bootstrap-server <fqdn>:9092 \
     --admin.config /opt/kafka/config/client.properties \
     --election-type UNCLEAN --topic ozon_s2s_events --partition 292
   ```
   При живом лидере из ISR контроллер отвечает `Valid replica already elected` —
   сначала стоп лидера, потом election.
3. Лидером стал 20003 (его лог консистентен), 21002 вошёл в ISR.
4. `systemctl start kafka-broker` на 22002 — догнал нового лидера, вернулся в ISR.
5. Итог: `Isr: 20003,21002,22002`, under/at min ISR = 0. Расхождение было только
   в хвосте старого лога 22002 (фактических потерь у консьюмеров не зафиксировано).

Дополнительно: 22006 (`6.broker...rc`) кто-то запустил параллельно — 57 "at min ISR" ушли сами.

## Грабли

- **kafka-leader-election.sh не принимает `--command-config`** — только `--admin.config`
  (joptsimple UnrecognizedOptionException). Остальные тулы (`kafka-topics` и т.д.) —
  с `--command-config`.
- Без `HEAP_OPTS=-Xmx512m` тул падал `OutOfMemoryError: Java heap space` на брокере.
- `kafka-topics --describe --topic X --partitions N` — флаг `--partitions` тут только для
  create/alter (мусорный usage-вывод); фильтровать полный describe через grep.
- Kafka 4.x: после мувa партиции в `<name>.stray` брокер при старте кидает
  `KafkaException: Found directory ... is not in the form of topic-partition` и не пересоздаёт
  реплику — `.stray` нужно удалять полностью (`rm -rf`), а не оставлять рядом.
- `--bootstrap-server localhost:9092` не работает: сертификат без SAN localhost —
  подключаться по FQDN хоста.
- Алерты Grafana (at/under min ISR) отстают — после фиксов перепроверять `kafka-topics
  --describe --at-min-isr-partitions / --under-min-isr-partitions` (= 0).
