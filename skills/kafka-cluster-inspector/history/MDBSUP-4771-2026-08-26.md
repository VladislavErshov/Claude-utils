# MDBSUP-4771 — modify_cluster (resize downscale) frontlogs-adtech-kafka

Дата: 2026-08-26. Кластер `frontlogs-adtech-kafka` `dbee9a79-1edf-41ca-b194-3f25cc1d425a`
(ns infra, 16 брокеров × dc hc/kc/pc/rc + 3 контроллера + 1 CC). Операция
`4c022695-91ec-45bf-b251-59ec348a3c61` modify_cluster — даунгрейд c.large (16/32G) → c.small (8/16G).
Связана с выездом из Пахры (TRG-229683 — hosts migration).

## Причина

5 ранов операции (19–26.08) падали на child `..._modify-broker_resize-broker_rc_3`
(`resizeInstanceKafkaBroker` для `3.broker.frontlogs-adtech-kafka.rc.one-infra.ru`):
one-cloud master 400 `ServiceValidationException: "Task instance ... cannot start by either
reason. Once resolved, it will start automatically"` — облако мигрировало 5ТиБ-хосты
(таргеты под большие диски искались долго, см. комментарии в тикете). Workflow исчерпал
ретраи раньше, чем облако закончило миграцию: последний ран failed 14:23 МСК, а миграция
3.broker.rc завершилась в 14:11 (4.broker.rc — 14:22), т.е. к моменту проверки всё уже сошлось.

## Диагностика

- Прод-БД: операция failed, attempts_left=0, in_processing=true (блок «Already has unapplied operation»).
- Draft-версия 219663: preset c.small 8 vCPU/16GB, units только hc/kc/pc — rc в units НЕ входит
  (alloc rc-хостов уже был 8/16 — вероятно, rc добавили в кластер позже draft).
- mcc по всем 4 ДЦ (`-c <dc>`, defaultCloud ic — обязательно указывать облако ДЦ!):
  demand=allocated=vCPU=32 MEM=64G на сервис broker.* в каждом ДЦ — целевой resize облако применило;
  все 16 инстансов RUNNING/RESERVED, `systemctl is-active kafka-broker` = active на всех.
- Temporal: RUNNING-ранов операции нет.

## Исправление

1. **Temporal Reset** (см. [MDBSUP-4832](MDBSUP-4832-2026-08-26.md)): GET history failed-рана → первый
   `WORKFLOW_TASK_COMPLETED` eventId=4 →
   `POST /api/v1/namespaces/default/workflows/4c022695.../reset?resetType=FirstWorkflowTask&requestId=<uuid>`
   (cookie `_csrf` + header `X-CSRF-Token`, body `{"requestId","workflowTaskFinishEventId":4}`).
   Новый run `c10a05a1-...` → **COMPLETED** (~минуты: облако уже в целевом состоянии).
2. Прод-БД (callback не сработал — status остался failed): `docker cp` SQL + `psql -f`:
   ```sql
   UPDATE operations SET status='done', in_processing=false, finished_ts=now(), error_message=NULL
   WHERE id='4c022695-91ec-45bf-b251-59ec348a3c61' AND status='failed';
   ```
   Верификация: done, in_processing=f; незакрытых операций по кластеру 0.

## Грабли сессии

- mcc defaultCloud = `ic`: `mcc instances` без `-c <dc>` ищет только в ic-облаке →
  EntityNotFoundException «No instances found» для кластеров в других ДЦ. Для hc/kc/pc/rc
  всегда `-c <dc>`.
- Reset-ран workflow COMPLETED, но operations.status остался failed — callback mdb-processing
  по reset-ранам не проставляет статус (в MDBSUP-4832 один из трёх проставился сам, здесь нет).
- История workflow: `GET .../workflows/{wid}/history?runId=<run>` (не `/runs/{run}/history`);
  ссылка failure на `initiatedEventId=508` относится к child-рану, не к родителю (у родителя 25 событий).

## Итог

Операция done, блокировка изменения настроек кластера снята. Рекомендация клиенту из тикета
(уменьшить диски/увеличить число брокеров) остаётся открытой.
