# MDBSUP-5508 — add_hosts (controller, sc): 404 Parent queue not found

Дата: 2026-09-17. Кластер: otvet-dev (a12b50f8-3cb9-4fc3-83a1-630b2a9e0617), Kafka,
environment=dev, project_id=182 (otvet). Операция: 7717c37d-8074-4778-be27-0d4a2cc22761
(add_hosts, контроллер в sc). Контекст — миграция кластера в SC (MNTPORTAL-667, On Hold).

## Цепочка падения

- operations: failed, attempts_left=0, in_processing=true, finished_ts=null,
  error «Controller upscale failed in 1 DC(s): [sc]». В host_state sc-хостов нет.
- Temporal: upscaleKafkaControllerInCluster (workflowId=operationId, 2 failed run'а)
  → дети `upscaleKafkaControllerInDc_{hc,pc,rc,sc}`; hc/pc/rc ok,
  sc: activity `cloud_submitQueueIfNeeded` → `CloudServiceImpl.submitQueue`
  → мастер sc: `404: Parent queue otvet.db.dev.mdb.prod not found`
  (RETRY_STATE_MAXIMUM_ATTEMPTS_REACHED) → родитель PARTIAL_UPSCALE_FAILURE (non-retryable).

## Корневая причина

На мастере облака sc не заведена родительская очередь проекта `otvet.db.dev.mdb.prod`
(есть только `otvet.db.production.mdb.prod` + `.batch`). В hc/pc/rc она есть.
У других проектов dev-ветки в sc существуют (odkl.db.dev.mdb.prod, mdb10xxx.db.dev.mdb.prod) —
dev в sc работает, просто ветку otvet.db.dev не создали при подготовке миграции.
Код mdb-processing корректен: submitQueueIfNeeded создаёт кластерную очередь, но не
родительскую — это инфраструктурная предподготовка нового ДЦ.

## Фикс

1. `mcc addqueue -c sc otvet.db.dev.mdb.prod` → очередь создана, но **STOPPED** и без
   product-меты.
2. `mcc submit -t queue` манифестом с `"state":"RUNNING"` по существующей очереди —
   **state не меняет** (update игнорирует state; `mcc start` для очередей не работает —
   «Neither service or instance could be found»).
3. Рабочий путь: `mcc --local -n infra -c sc --auto_solve withdraw --type queue
   otvet.db.dev.mdb.prod` (очередь пустая; уравнение-подтверждение) → пересоздать сразу
   манифестом `{"type":"queue","namespace":"infra","name":"otvet.db.dev.mdb.prod",
   "state":"RUNNING","meta":{"product":"4811"}}` → state=RUNNING.
   Эталон: audit `odkl.db.dev.mdb.prod` в sc — «Queue created with manifest …
   "state":"RUNNING"…» (d.moskvin, 31.07). Механика описана в
   mcc-host-worker/commands/queues.md.
