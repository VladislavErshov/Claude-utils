# MDBSUP-4937 — ozon-products-events (adtech): delete контроллера rc 6 раз падал на RELOAD_FAILED (cloud-апдейт инстанса блокировал proxy-ssh)

Кластер: `ozon-products-events-adtech-kafka` (5ddbff47-25c6-4c9e-a2cd-08e7067a46e2), ns=infra.
4 ДЦ (kc/pc/rc/uc) × 8 брокеров; контроллеры 10001@kc / 11001@pc / 12001@rc / 13001@uc
(uc добавлен 24.08); CC в rc. 24.08 были add_hosts (брокеры, деплой n.dergunov 17:58) —
инстансы rc-брокеров 1-4,6-8 обновлены 24.08 17:14–17:44, инстанс 5 — нет (см. ниже).

Операция: delete_hosts контроллера rc `2655e340-9ea9-4ef9-ad07-374fd4dc700e`
(host.dc=rc, shard=null). 6 ранов 12:25–15:56 UTC 27.08, все FAILED, attempts_left=0.

## Симптом

Раны 1–5 (~15 мин каждый): broker-reload по ДЦ kc→pc→rc→uc, 31/32 брокеров проходят за
~15 сек, падает только child `<opId>_update-broker-config_rc_4` (4.broker...rc):
`kafka_host_restartBrokerInstanceSsh` «завершается» за 1.2 сек, затем
`kafka_host_pingSshRestartedBrokerInstanceReady` 15 минут (timeout 900s) возвращает false
→ «Broker instance ... is not ready yet (ping is not ok)» → non-retryable
`Config reload failed for hosts: [4.broker...rc]` → операция FAILED.

Ран 6 (15:55, 62 сек): не дошёл до reload — vault-таймаут в `kafka_host_getLeaderId`
(`Failed to get secret from zkv/mdb/adtech/kafka/...super`, HttpTimeoutException).

## Корневая причина (раны 1–5)

Рестарт-команда через one-cloud proxy sshExec **не долетала до хоста вообще**:
на 4.broker.rc за 12:25–19:17 нет НИ ОДНОГО следа ни confp (`/one/logs/confp.log` пуст),
ни systemd-рестартов; JVM брокера писала kafka-broker.out.log непрерывно все часы.

Причина: облако в это время катило сервис-апдейт на rc-брокеров и инстанс 4 висел в
переходном состоянии (в 15:55 в getInfosForServices — instance state STOPPING, сервис
UPDATING). Proxy не исполняет команды в останавливаемом инстансе. Облако довело апдейт
только к **19:17:51** (systemd-старт 19:17:36, recovery 8 сек) — ~7 часов зависания.

Сопутствующее: контроллер rc флоу остановил в первом ране (JVM exited 12:25:15 UTC,
+4 сек от старта рана — это ожидаемо для delete), но удаление инстанса из облака висело
не завершённым (controller@rc: unfinished=1, инстанс RUNNING/UNAVAILABLE, «Broker is dead»).
broker@rc при этом навсегда застрял в UPDATING 7/8: инстанс 5 не может принять апдейт
«cannot fit to current minion and instance is not movable: rejected srvr24196: scheduling
restricted» — хвост ещё от 24.08 (ресурс спеки vCPU=64/MEM=256G не влезает на старый миньон).

## Код-проблемы mdb-processing (кандидаты)

1. `kafka_host_restartBrokerInstanceSsh` завершается успешно за 1.2 сек, даже когда
   команда не исполнилась на хосте — нет проверки результата sshExec (exit code / эффект).
   Ping-фаза потом честно ждёт 15 минут и роняет child.
2. All-or-nothing reload: один хост роняет всю операцию (см. также
   temporal-worker/history/2026-08-27-upscale-kafka-controller-reload-failures.md).
3. error_message хранит только последнюю ошибку рана: Jira-сообщение «Config reload
   failed» маскировало vault-таймаут рана 6 — историю ранов смотреть только в Temporal
   listing (runId в history API игнорируется).

## Диагностика (что дало ответ)

1. Temporal listing по operationId → 6 ранов; history последнего рана → vault-таймаут.
2. Listing `WorkflowId STARTS_WITH '<opId>'` → все children: падает только `_rc_4`,
   каждый раз ~13.5 мин (ping-timeout), остальные 31 — OK.
3. History `_rc_4`: input/host корректный, ping 11×false — рестарт «прошёл», хост не proof.
4. На хосте: journalctl/confp.log — ноль следов рестартов; out.log — JVM жила непрерывно.
   → команда не исполнялась, а не «брокер не поднимался».
5. getInfosForServices из history рана 6 (base64-decode payloads) → instance 4 STOPPING,
   сервис UPDATING — облако само трогало инстанс.
6. mcc status сервиса: progress «Update: 7/8», у инстанса 4 «since 19:17:51» — апдейт
   долдился, инстанс стабилен.

## Решение

После того как облако само довело апдейт инстанса 4 (19:17) и vault отвалился транзиентно
(чужой updateConfigKafkaBroker прошёл в 16:43) — рестарт операции в ~22:3x → **COMPLETED**
(done, finished 22:39 MSK), контроллер rc удалён из host_state. Тикет закрыл пользователь.

Хвосты: broker@rc UPDATING 7/8 (инстанс 5, scheduling restricted — отдельная задача);
в operations у закрытой операции осталось `in_processing=t`.

## Уроки

- RELOAD_FAILED на ОДНОМ хосте с вечным ping=false: сначала проверять, дошла ли команда
  до хоста (journalctl -u kafka-broker + /one/logs/confp.log), а не «почему брокер не
  поднимается». Нет следов = proxy не исполнил.
- Instance state STOPPING / сервис UPDATING в getInfosForServices = облако катит апдейт,
  proxy-ssh в такой инстанс не работает → reload обречён; ждать завершения апдейта.
- Рестарт операции имеет смысл только ПОСЛЕ стабилизации инстанса — иначе тот же фейл.
