# test-downgrade5-mdbdev-kafka — даунгрейд 4.3→3.8 (2026-08-09, run 1)

Кластер `test-downgrade5-mdbdev-kafka` был изначально создан с версией Kafka 3.8. Затем поднят до 4.3 по инструкции дежурного, **но инфраструктура (docker-образ, confp-конфиги, systemd-юниты) и БД (бизнес-данные, `__consumer_offsets`) остались на версии 3.8** — то есть 4.3 была поднята "поверх" 3.8-инфраструктуры.

**Why:** Тестовый стенд для отработки процедуры даунгрейда 4.3 → 3.8 (KRaft, in-place). Имеет смысл при оценке рисков: грабли #18 (retention удаляет .log) и #21 (`__consumer_offsets` с 4.3 records ломает group coordinator) сработали в чистом виде, т.к. данных было мало и кластер был свежим.

**How to apply:** При анализе даунгрейдов реальных prod-кластеров (где 4.3 стоит давно) учитывать, что test-downgrade5 — лёгкий случай: мало данных, свежий кластер, инфраструктура уже 3.8-совместима. Не экстраполировать успех напрямую на prod без запаса по времени и полного бэкапа `log.dirs`. Процедура 2026-08-09 прошла успешно, бизнес-данные сохранены полностью через `retention.ms=-1`.
