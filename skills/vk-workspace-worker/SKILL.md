# VK Workspace Worker

Скилл для работы с VK Workspace через MCP-сервер `vkws` (инструменты `vkws_*`). Используй, когда нужно прочитать чат/тред, найти сообщение, скачать файл или написать кому-то — особенно в контексте инцидентных чатов и тредов с разборами.

## Главные правила

1. **Работа — только через MCP `vkws_*`.** Не выдумывай REST-вызовы и не проси пользователя копировать текст вручную, если всё умеет MCP.
2. **Стиль сообщений — через скилл `text-writer`** (раздел VK Workspace): человечный мессенджер-стиль, без нейро-маркеров и маркдауна. Требование пользователя, обязательнее грамматической идеальности.
3. **Любое исходящее сообщение — сначала черновиком пользователю в чат агента.** Отправка (`vkws_send_message` / `vkws_send_message_rich`) только после явного «ок» / «давай» / «отправляй». Исключение — если пользователь сам продиктовал точный текст.
4. **Язык — русский**, как в целевом чате. Тон зеркалишь конкретному чату (инцидентные — короче и суше, рабочие треды — свободнее) — детали в `text-writer`.

## Рабочий процесс

1. **Проверь сессию**: `vkws_session_status`. Если `authenticated=false` — спроси email у пользователя, затем `vkws_auth_login(exec=true, email=...)`. Если в статусе есть `canonical_email` — использовать его без повторного вопроса.
2. **Ссылки вида** `https://webim.internal.myteam.mail.ru/message/v1/<base64>` — декодируй base64: получаешь `<sn>/<msgId>` (SN может быть stamp чата). Stamp ≠ SN: сначала `vkws_resolve` по stamp, получишь реальный `SN` вида `123456@chat.agent`.
3. **Чтение истории**: `vkws_get_history_page` (count отрицательный = назад от from_msg_id) или `vkws_get_latest_messages` (хвост). Для сообщения по msgId: возьми `-N` сообщений ДО него и `+N` после (from_msg_id = msg_id соседнего).
4. **Треды (ответы на сообщение) живут в ОТДЕЛЬНЫМ чате**, а не в основном диалоге. SN треда (`<другой-id>@chat.agent`) найдётся через `vkws_search_messages` со scope=`chat_threads` (sn = SN чата-родителя) — в выдаче у каждой записи `dialog_sn` треда. Дальше читай тред как обычный диалог. Прямой SN `<chat>.<msgId>@chat.agent` не резолвится — не пытайся.
5. **Поиск**: `vkws_search_messages` — scope `dialog` / `all` / `chat_threads` / `threads_feed`; фильтры по автору и датам (dd.mm.yyyy). Поиск по подстрокам русского текста работает («кафк» найдёт «Кафка»).
6. **Файлы**: `vkws_download_file` (URL из `attachments`/`captionedContent`). Если скачался маленький JSON-файл вида `{"status":200}` — это заглушка, файл реально не скачался: скажи пользователю и попроси содержимое другим путём.
7. **Отправка**: `vkws_send_message` для простого текста. Ответ в тред — просто сообщение в SN треда. Форматирование (bold, упоминания, цитаты) — `vkws_send_message_rich`; формат-оффсеты считаются по символам plain-строки, не по байтам UTF-8.

## Стиль сообщений

Получай из скилла **`text-writer`** (раздел VK Workspace) — там агрегированы все правила
человечного стиля (без маркдауна, длина, тон, обращения, эмодзи, голые URL, черновик
в итоговом виде). Этот скилл определяет только доставку: сессия, треды, rich-формат.

## Технические грабли (выучено на практике)

- `getHistory` с 40000 «Failed to resolve» — почти всегда неправильный SN: stamp вместо chat-SN. Сначала `vkws_resolve`.
- Цитата внутри сообщения приходит как part с `mediaType=quote` (внутри sn/msgId исходного сообщения) — при чтении истории склеивай text-части.
- `persons` в ответе истории — расшифровка SN → ФИО, используй для имён вместо голых адресов.
- Запланированные сообщения: `vkws_send_scheduled_message` / `get_scheduled_messages`; отмена — `cancel_scheduled_messages`.
- Chat-инфо и состав участников: `vkws_get_chat_info` (по sn или stamp), точный lookup юзера — `vkws_resolve`, поиск людей — `vkws_search_entities`.
