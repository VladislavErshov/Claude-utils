# MDBSUP-4925 — UI показывал 2 зоны контроллеров вместо 3 (ecom-fsa)

Кластер: `08f5ed31-fdc7-4505-a3fd-69d39724bdc2` (ecom-fsa-adtech-kafka, Kafka).
Симптом: в «редактировать кластер» только 2 зоны (KC, PC), при сохранении — ошибка
«нужно 3 или 5 контроллеров». Реально контроллеров 3: kc/pc/uc (host_state корректен).

## Причина

Наследие MDBSUP-4752: тогда add_hosts (добавление uc-контроллера) упал, операцию закрыли
руками и вставили хост в `host_state`, но `controllerDcs` в `db_cluster_version` остался
без `uc`. 27.08 delete_hosts удалил hc-контроллер → свежая версия 238512 получила
`controllerDcs ["kc","pc"]` (старый список минус hc). UI читает зоны из последней
scheduled-версии → 2 зоны, валидация режет сохранение.

## Фикс (прод, port-forward 53480, 27.08.2026)

Аналогично MDBSUP-4877: jsonb_set controllerDcs → `["kc","pc","uc"]` в актуальных
scheduled-версиях 238512 (только controllerDcs; units уже были ок), 235728 и 221461
(плюс units → kc/pc/uc, убрали мёртвый hc). Версии 2025 года (10663 и старше) не трогали.
UPDATE 3, верифицировано SELECT-ом.

## Паттерн

После ручного добавления хостов через host_state (закрытие упавших add_hosts) надо
проверять и `db_cluster_version`: `controllerDcs` + `hosts_params.units` должны совпадать
с реальными контроллерами, иначе UI modify-форма ломается на валидации.
