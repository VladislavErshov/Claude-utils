# MDBSUP-4867 — Миграция лежащего RC-контроллера (audit-mdb10154-kafka, LOST_MINION)

- Дата: 2026-08-25
- Кластер: `132f9afc-b9a0-4bb8-b282-0a4ee8586dfb` (audit-mdb10154-kafka, Kafka 4.3 KRaft, ns infra)
- Хост: `1.controller.audit-mdb10154-kafka.rc.one-infra.ru`

## Диагностика

- В прод-БД зависших операций нет (только create_cluster = done).
- `mcc instances "<FQDN>"` → `state=FINISHED, outcome=LOST_MINION,
  "rejected required storage's minion: not running"`.
- `mcc tool_status --type storage <queue>/controller` → volumes data(20g)+logs(10g) формально
  NORMAL, но на миньоне `srvr24018`, а `mcc minion_storage srvr24018` → state=STOPPED с 2026-08-23.
- Симптом в UI MDB: все метрики хоста unknown.

## Шаги (выполнено)

1. **Delete дисков мёртвого хоста** (только его volumes, НЕ весь storage — он общий на 3 реплики):
   `mcc --local -n infra delete "<uuid1>,<uuid2>" -f yaml` (uuid из tool_status).
   По UUID `--state` НЕ указывать (ValidationException: State should not be used specifying volume by uuid).
   Требует решить уравнение-подтверждение (`N*M` / `N mod M`) — меняется между запусками;
   expect/pexpect у нас не взяли (mcc молчит в pipe) — пользователь дропнул диск руками.
   Ответ: "Volumes contain data. New empty volume will be created."
2. **Purge** (пользователь): `mcc purge <queue>/controller srvr24018` — у нас "none to purge"
   (диск уже удалён на шаге 1).
3. **Start сервиса**: `mcc --local -n infra start controller.audit-mdb10154-kafka`
   → облако задеплоило инстанс на новом миньоне `srvr23991`.
4. **Wait**: `mcc tool_status --type task <FQDN>` → STARTING → RUNNING (~2 мин, DEPLOYING:
   Waiting sandbox / Configuring ACL).
5. **Верификация**: sshexec → `systemctl is-active kafka-controller` = active;
   в kafka-controller.out.log — `Kafka Server started` (вход в KRaft-кворум).

## Итог

Хонт пересоздан с новым диском на живом миньоне, контроллер в кворуме. KRaft-кворум был 2/3 на время работ.

## Грабли

- `mcc wait` не имеет `--state` — синтаксис `mcc wait <name> <value>`, проще поллить
  `tool_status --type task <FQDN>` до RUNNING.
- Уравнение mcc delete не решить через echo stdin (меняется per-run); expect/pexpect не взялись
  (spawn молчал, вероятно tty/pipe). Рабочий вариант — интерактивно руками.
- `--state NORMAL` + UUID → ValidationException; по списку UUID state указывать нельзя.
