# MDBSUP-4933 — CLIENT LIST на adtech-cache: кто подключён перед удалением (2026-08-27)

Тикет-запрос (не инцидент): пользователь хочет удалить кластер и просит узнать IP
подключённых клиентов. Кредов у пользователя нет — снимаем сами через mcc.

## Кластер
- `adtech-cache-recommender-redis` (Redis Cluster, 18 шардов × 3 ДЦ dc/kc/rc),
  cluster_id `1c1d4751-108e-4333-b40a-2a12fbc767a0`, ns infra, project recommender.

## Метод
1. Хосты — из прод-БД (`host_state` по cluster_id) или паттерна `1.shard{N}-db.<queue>.<dc>`.
2. **Один** `cluster nodes` с любой ноды даёт всю топологию → список мастеров.
3. `CLIENT LIST` только на 18 мастерах — реплики не нужны: кластерные клиенты ходят
   через мастера, на репликах будут только репликационные/служебные коннекты.
4. Авторизация — канон из [../SKILL.md](../SKILL.md) «Подключение»:
   `redis-cli --user master --pass $(awk '$1=="user" && $2=="master" {gsub(/^[^>]*>/,"",$0); gsub(/ .*/,"",$0); print}' /etc/redis/acl/users.acl)`.

## Грабли: парсинг `cluster nodes` в Redis 7+
- 2-е поле = `addr@cbus,hostname` (склеены **запятой**, не отдельное поле!),
  роль — **3-е** поле (`master` / `slave <id>` / `myself,master`), мастера в конце
  имеют слоты, реплики заканчиваются на `connected`.
- Хостнейм мастера: `awk '$3=="master"{sub(/.*,/,"",$2); print $2}'`.
- Наивный `grep 'master$'` не работает (мастера заканчиваются слотами).

## Фильтрация «своих» коннектов в CLIENT LIST
- `flags=S`, cmd=`replconf` — репликация от реплик кластера (fd00-адреса нод).
- `name=one-cloud-ops` (jedis, `cluster|nodes` / `acl|getuser`) — служебные коннекты
  оператора: в этом кейсе 10.205.39.43, 10.218.48.246 + два fd00.
- `127.0.0.1` cmd=`client|list` — мы сами.
- Всё остальное = клиенты приложений. Здесь их не оказалось → кластер свободен.
