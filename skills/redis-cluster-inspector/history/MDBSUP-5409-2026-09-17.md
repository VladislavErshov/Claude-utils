# MDBSUP-5409 — chepusher: нельзя добавить реплику — валидатор `shardName` не принимает легаси `shard-N` (2026-09-17)

Тикет (автор Валеев Марат, создан 2026-09-14): «при попытке добавить реплику через UI —
`replicas[0].shardName: должно соответствовать "shard\d+"`, Bad Request / Validation failed».

Кластер: `chepusher` `4fa15ad0-1e7d-45b7-a94d-d84f11051ad9`, Redis sharded,
создан 2025-01-15, **80 шардов** `shard-1`…`shard-80` (db_shards.id 1986–2027, 40402–40439),
хосты в hc/kc/pc (+ec на шардах 43/45/48), FQDN вида `1.shard-N-db.chepusher-vkcm-redis.<dc>.one-infra.ru`.

## Диагноз

- В прод-БД (`backstage_plugin_mdb.db_shards`) шарды кластера реально именованы `shard-N`
  (через дефис) — **легаси-формат** от создания кластера.
- Валидатор API add-replica (mdb-data, bean-validation `@Pattern`-стиля) требует
  `shardName ~ shard\d+` — имена с дефисом отклоняются ещё до создания операции.
- Реплику в существующий шард добавить нельзя в принципе: запрос несёт имя шарда
  как есть, обходного пути через API нет.

## Что проверено (прод-БД, read-only)

- Зависших операций нет: последние 5 операций `done` (последняя `sys_update_cluster`,
  finished 2026-08-12). Кластер заблокирован только валидацией, не операцией.
- **Масштаб:** среди Redis-кластеров chepusher — **единственный** с dash-именованием
  (19 675 не-удалённых шардов в формате `shardN`; dash-шардов всего 217 по всем типам БД).
  Регресс на остальных пользователях не воспроизведётся — баг бьёт только по легаси-кластерам.

## План

1. **Продуктовый фикс (правильный путь):** баг в mdb-data — regex валидатора ослабить
   до `shard-?\d+` (или нормализовать имена). **Заведён MDBDEV-3454** (Bug, Relates к
   MDBSUP-5409), 2026-09-17.
2. **Workaround (не рекомендован):** переименование шардов в прод-БД `shard-N` → `shardN`
   — рискованно: FQDN существующих хостов содержат `shard-N-db`, возможны расхождения
   с оператором/облаком/рендером имён новых хостов. Без глубокого разбора не делать.
3. Комментарий в MDBSUP-5409 с диагнозом (через text-writer).

## Грабли сессии

- Docker Desktop был заморожен — `docker exec` и даже `docker ps` висели; прод-БД
  подняли через локальный psql из libpq: `/opt/homebrew/opt/libpq/bin/psql -h localhost
  -p 53480 -U backstage` (psql в PATH отсутствует, бинарник libpq — есть).
- Туннель tsh «висел» (LISTEN есть, соединение не отвечает) — пересоздать через
  `mcc tp-port-forward 1.db.mdb-etp-pgsql.pc.wan.idzn.ru:7432 --local-port 53480`.
- Прод-схема: `db_cluster` без колонки `status`; `db_shards.shard_name` (не `name`).
