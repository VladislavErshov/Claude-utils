### Ключевая находка

**Валидатор brokerConfig требует, чтобы параметры уже присутствовали в baseline-конфиге.** Нельзя добавить новые параметры — только изменить существующие.

Baseline `db_cluster_version.cluster_params.kafkaParams.brokerConfig.config` для test-sel-1:
```json
{"compression.type": "uncompressed"}
```

Только `compression.type` проходит валидацию. `num.io.threads`, `log.flush.interval.messages`, `default.replication.factor`, `min.insync.replicas`, `unclean.leader.election.enable` — отбиваются.

**tosAgent=true требует docker-образ ≥ 2.4.0** — на этом кластере образ ниже.

## Выводы

1. **Валидатор brokerConfig в mdb-data** (`KafkaClusterModificationValidator`) сверяет ключи из запроса с ключами в **текущем** `cluster_params.kafkaParams.brokerConfig.config` baseline-версии. Новые ключи добавить нельзя.
2. **tosAgent=true** требует docker-тег версии ≥ 2.4.0 — проверка в валидаторе.
3. Workflow: `modifyController` (resize) запускается до `modifyBroker` — если controller resize падает, broker config не применяется.
4. Для тестирования изменения brokerConfig нужно: либо подобрать кластер с rich baseline (test-resize содержит `num.io.threads`), либо добавить параметры в baseline вручную.
